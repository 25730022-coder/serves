# 책방틈 (Bookbangteum)

> 취향에 맞는 독립서점을 발견하고, 책방과 산책을 연결하는 모바일 중심 웹서비스

**최신 버전:** v0.6 (2026-11-23)  
**버전 기록:** v0.6 → v0.5 → v0.4 → v0.3 → v0.2 → v0.1 (최신순)  
**문서 구성:** 1. 변경이력 관리 → 2. PRD → 3. 공통 개발·운영 정보

이 문서는 각 시점의 **기획 요구사항과 실제 소스에 구현된 기능을 구분**해 기록한다. 버전 날짜는 각 버전의 기준일이며, 모든 개별 기능의 실제 코딩 날짜를 뜻하지 않는다.

## 1.2 변경 상세: v0.5 → v0.6 (2026-11-23)

- **CHG-701 · 저장소 이원화(하이브리드 데이터 저장):**
  - **즐겨찾기(`bookstore.favoriteIds`):** 기기 내 즉각적인 조회와 비로그인 접근 편의를 위해 기존과 동일하게 브라우저 **`localStorage`**에 저장.
  - **그 외 데이터(회원·후기·방문 기록·코스·공통 데이터):** 브라우저 단일 저장소의 한계(기기 변경 시 유실, 다중 사용자 공유 불가)를 보완하기 위해 **외부 클라우드 데이터베이스(Cloud DB) 및 정적 JSON 데이터 영역**으로 분리 저장하도록 구조 개편.
- **CHG-702 · 새소식 자동 수집 파이프라인(GitHub Actions):**
  - `.github/workflows/update-news.yml` 및 `scripts/fetch_news.py` 추가.
  - 3시간마다(또는 수동 실행 시) Google 뉴스 RSS에서 최근 독립서점 기사를 수집하여 `data/news.json`을 갱신하고, 변경 사항이 있을 때만 자동 커밋·푸시.
- **CHG-703 · 홈 화면 피드백 반영(자동 스와이프·인기 코스 가독성):**
  - `'오늘 이런 책방 어때요?'` 추천 책방 카드(최대 6개)가 수동뿐만 아니라 **자동 스와이프**로 전환되도록 개선.
  - 인기 코스 카드에서 **코스 제목**과 하단 메타 정보(**작성자 · 장소 · 소요시간 · 코스 순서**)가 명확히 구분되도록 레이아웃 정리. 코스 제목이 길어 화살표(`>`) 기호만 다음 줄로 밀리거나 중간에 글이 끊겨 보이는 현상을 방지하기 위해 폰트 크기 축소 및 줄바꿈 처리 보완.
- **CHG-704 · 책방 탐색·코스 생성 플로우 피드백 반영:**
  - 책방 탐색 진입 시 회원가입 때 설정한 조건으로 필터 패널이 자동 펼쳐지던 동작을 수정하여, **전체 조건이 제공되되 초기 진입 시에는 필터 패널이 닫혀 있도록(접힘 상태)** 변경.
  - **새 코스 만들기**에서 1번 책방 선택 시 2·3번 장소가 자동으로 채워지던 방식을 제거하고, **2·3번 장소도 사용자가 직접 선택**하도록 변경.
  - 코스 생성 직후 노출되던 `'코스 편집'` 단계를 삭제하고, **마이페이지 내 저장 코스 목록에서 아이콘 버튼으로 편집·삭제**를 수행하며 **공개/비공개 전환은 토글(Toggle) 스위치**로 간편 수정하도록 개편.
- **CHG-705 · 메뉴 명칭 변경('나의 책방' → '마이페이지'):**
  - 기존 `'나의 책방'` 메뉴 및 화면 타이틀을 직관적인 **`'마이페이지'`**로 일괄 변경.
- **CHG-706 · 서점 상세 후기 탭 및 입력·노출 순서 개편:**
  - 서점 상세 페이지에서 `'책방 정보'` 옆 탭 명칭을 `'줄글 후기'`에서 **`'후기'`**로 변경.
  - 후기 작성 및 조회 시 **한 줄 후기가 최상단에 먼저 노출**되고, 그 아래에 **분위기 / 공간 시설 / 책 큐레이션** 항목이 선택 옵션으로 배치되도록 순서 재구성.
- **CHG-707 · 유지:** 서점 데이터(`bookstores-local.json` 100개 + `bookstores-api.json` 200개), 주변 장소(`places.json` 16개), 썸네일 40종·코스 이미지 10종은 v0.5와 동일.
- **CHG-708 · 코드/파일:** `.github/workflows/update-news.yml`, `scripts/fetch_news.py`, `data/news.json` 추가; `index.html`, `css/style.css`, `js/app.js` 수정.

## 1.3 변경 상세: v0.4 → v0.5 (2026-11-16)

- **CHG-601 · 썸네일 에셋·비중복 랜덤 호출:** `asset/` 하위 경로에 **책방 썸네일 40개**와 **인기 코스 이미지 10개**를 제작해 넣고, 한 화면 내에서 사진이 중복되지 않도록 랜덤 호출 코딩 적용. 전 화면에서 썸네일 사진 비율을 동일하게 통일.
- **CHG-602 · 홈/히어로 UI 개편:** 메인 히어로 영역에 모션 적용. 영문 소타이틀(`DISCOVER`, `NEWS & STORIES` 등) 및 메인/섹션 서브타이틀 전체 삭제. `'다시 뽑기'` 텍스트 삭제 후 홈 화면 버튼 클릭 시 새로고침되도록 변경. `'오늘 이런 책방 어때요?'` 추천 책방을 기존 2개에서 **최대 6개 가로 스와이프** 방식으로 변경.
- **CHG-603 · 새소식 크롤링 데이터 표시:** 외부 검색 링크 연결 방식을 제거하고 크롤링으로 가져온 **최신 뉴스 3개 + 책방 행사 2개**를 날짜 기준으로 가져와 `뉴스`·`행사` 태그와 함께 노출.
- **CHG-604 · 책방 탐색·상세 피드백 반영:**
  - **책방 탐색:** `'상세보기'` 텍스트를 삭제하고 아이콘으로 변경. 상단 헤더 흔들림 보정(헤더 고정) 및 바디에 `'이전으로 돌아가기'` 추가.
  - **책방 상세:** 전화번호 줄바꿈을 제거해 한 줄로 표시, 주소 옆에 복사 아이콘 추가, 하단에 별도 지도 칸을 만들어 지도 호출.
- **CHG-605 · 코스 피드백 반영:** `'선택된 조건이 없어요. 필터를 눌러 조건을 추가해보세요'` 안내 문구 및 `'정렬:'` 텍스트 삭제, 상단 헤더 흔들림 보정(고정), 코스 화면 내 샘플 지도 이미지 출력.
- **CHG-606 · 나의 책방(로그인 후) 피드백 반영:** 즐겨찾기에서 `'상세보기'` 텍스트 삭제 및 즐겨찾기 해제 버튼을 아이콘으로 변경, 즐겨찾기 썸네일 비율을 어디에서나 동일하게 통일. `'내 후기'` 탭을 선택한 뒤 홈이나 다른 화면에 다녀와도 항상 `'즐겨찾기'`가 먼저 나오도록 수정.
- **CHG-607 · 유지:** 서점 JSON 100+200, 장소 16, 공유 코스 7의 데이터 파일 및 `scripts/fetch_bookstores.py`는 v0.4와 동일.
- **CHG-608 · 코드/에셋:** `index.html`, `css/style.css`, `js/app.js` 수정; `asset/` 하위 책방 썸네일 40개 및 코스 썸네일 10개 추가.

# 2. PRD (Product Requirements Document)

# 서비스 한줄 소개
- 내 취향에 맞는 독립서점을 빠르게 찾고, 책방을 중심으로 산책·휴식 코스까지 계획하는 모바일 웹 서비스

# 배경과 문제 정의
- 독립서점을 찾는 사람은 지도 앱에서 "독립 서점"을 검색한 뒤, 책방을 하나씩 열어 보고, 블로그·SNS에서 **어떤 책을 다루는지 / 조용한지 / 혼자 가기 좋은지 / 앉아서 읽을 수 있는지**를 따로 확인해야 한다. 탐색 시간이 길고, 책방의 핵심 특징을 한눈에 비교하기 어렵다.

책방틈의 핵심 가치는 여러 책방을 많이 방문하는 것이 아니라 **"나에게 맞는 책방을 발견하는 것"** 이다. 산책은 서비스의 최종 목적이 아니라, 책방에서 책을 읽고 쉬기 전후의 여유로운 경험을 넓혀 주는 요소다.


## 2.1 PRD v0.6 — 2026-11-23 (최신)

### 제품 목표와 대상

- **목표:** 지역·취향·분위기별로 독립서점을 발견하고, 후기와 공간 정보를 참고해 방문할 책방을 정한 다음 산책 코스를 계획·저장한다.
- **대상:** 독립서점 탐방객, 혼자 책을 읽고 쉬려는 사용자, 산책과 책방 방문을 결합하려는 사용자.
- **환경:** 모바일 중심 반응형 정적 웹(HTML/CSS/JavaScript), 브라우저 저장소(`localStorage`) + 외부 데이터베이스/정적 JSON 이원화 저장 구조.

### 기능 우선순위

- **Must:** 책방 목록/검색, 전체 조건 필터(초기 닫힘 상태), 상세정보(전화번호 한 줄·주소 복사 아이콘·하단 지도 영역·'후기' 탭 내 한 줄 후기 최상단 노출), 출처 A/J 표시, JSON 로딩/오류 안내, 후기 작성 및 분위기 연동, 탐색·코스 상단 헤더 고정 및 바디 이전 복귀, 즐겨찾기(`localStorage`) 및 그 외 데이터(외부 DB·정적 JSON) 분리 저장.
- **Should:** 마이페이지(기존 '나의 책방' 명칭 개편 · 재진입 시 즐겨찾기 탭 기본 노출 · 해제 아이콘 · 상세보기 텍스트 제거 · 동일 썸네일 비율 · 저장 코스 아이콘 편집/삭제 및 공개/비공개 토글), 최근 본 책방, 새 코스 만들기(1·2·3번 장소 사용자 직접 선택 및 저장), 취향 설정·추천, 모바일 탐색 편의(TOP), 책방 썸네일 40개·인기 코스 이미지 10개 비중복 랜덤 호출, 히어로 모션 및 추천 책방 최대 6개 자동 스와이프, 인기 코스 제목·메타정보 분리 및 줄바꿈 가독성 보정, GitHub Actions 기반 자동 수집 뉴스·행사 데이터(`data/news.json`).
- **Could:** 새소식 자체 목록·상세 화면, 실시간 양방향 소셜 피드.
- **제외/미구현 구분:** 실시간 혼잡도·재고·결제·예약은 범위 밖.

### MVP 및 완료 조건

1. 사용자가 지역·테마·분위기 조건(초기 접힘 상태의 전체 필터)으로 서점을 좁히고 상세정보(주소 복사 아이콘·한 줄 전화번호·하단 지도·한 줄 후기 우선 노출)를 확인한다.
2. 서점의 기존 태그 및 작성된 후기의 분위기 정보로 탐색 결과를 판단한다.
3. 즐겨찾기는 `localStorage`에 즉시 저장·조회되고, 회원·후기·코스(1·2·3번 장소 직접 선택 및 저장)·공통 데이터는 외부 DB/정적 JSON 데이터 구조로 분리 관리된다.
4. 마이페이지에서 저장된 코스를 아이콘으로 편집/삭제하고 토글 버튼으로 공개/비공개 상태를 전환할 수 있다.
5. 한 화면에서 책방 썸네일(40개)과 코스 이미지(10개)가 중복 없이 랜덤 호출되고 전 화면에서 동일한 비율로 표시된다.
6. 데이터 로딩 실패 시 오류/재시도 또는 부분 로딩 안내를 제공한다.

### User Flow

- **A · 책방 발견:** 홈 검색/해시태그 또는 자동 스와이프 카드(최대 6개) → 책방 탐색(전체 조건 필터 펼쳐 선택) → 썸네일 카드 비교(아이콘 클릭) → 상세(주소 복사·하단 지도 확인) → 즐겨찾기(`localStorage`) 또는 후기(DB).
- **B · 후기 작성 및 필터:** 책방 상세 `'후기'` 탭 → 한 줄 후기 입력 후 분위기·공간 시설·책 큐레이션 옵션 선택 → 저장 → 책방 탐색 → 같은 분위기 필터 → 해당 책방 노출.
- **C · 코스 생성 및 관리:** 새 코스 만들기 → 1·2·3번 책방/주변 장소 직접 선택 → 샘플 지도 결과 확인 → 저장 → 마이페이지에서 아이콘으로 편집/삭제 및 공개/비공개 토글 전환.
- **D · 개인화:** 로그인 → 취향 설정 → 홈 맞춤 추천 → 책방 상세 → 마이페이지(항상 즐겨찾기 먼저 표시·아이콘 해제).
- **E · 최근 기록:** 책방 상세 방문 → 홈 최근 본 책방 → 카드 재방문 또는 카드별 삭제.

### 데이터 구성 및 저장소 이원화 (v0.6)

- **브라우저 `localStorage` 저장 영역:**
  - **즐겨찾기(`bookstore.favoriteIds`):** 비로그인 상태에서도 즉각 반응하고 기기별 개인 북마크를 빠르게 유지하기 위해 브라우저 `localStorage`에 저장.
- **외부 데이터베이스(Cloud DB) 저장 영역:**
  - **사용자·참여·개인화 데이터:** 회원 계정/프로필, 방문자 후기(한 줄 후기 + 분위기/시설/큐레이션 옵션), 방문 기록, 사용자 생성/공유 코스(공개/비공개 상태 포함), 취향 설정 등 기기 간 유지 및 사용자 간 조회·공유가 필요한 데이터는 외부 데이터베이스(BaaS/Cloud DB)에 저장. *(용어 구분: 서버형 저장소는 '데이터베이스', 저장소 내 정적 파일은 'JSON 데이터 스토어'로 구분)*
- **정적 JSON 데이터 파일 (`data/`):**
  - `data/bookstores-local.json` — 100개, 화면 출처 `J`.
  - `data/bookstores-api.json` — 200개, 화면 출처 `A` (`scripts/fetch_bookstores.py` 수집).
  - `data/news.json` — GitHub Actions(`scripts/fetch_news.py`)가 3시간 주기로 Google 뉴스 RSS를 수집해 갱신하는 최신 뉴스·책방 행사 데이터.
  - `data/places.json` — 주변 장소 16개.
  - `data/sharedCourses.json` — 기본 공유 코스 7개.
- **시각 리소스:** 메인 히어로 이미지(`asset/bookstore-hero.jpg`, 모션 적용), **책방 썸네일 40개**(`asset/thumbnails/`), **인기 코스 이미지 10개**(`asset/courses/`).
- **예외:** 누락된 서점 정보는 임의로 채우지 않으며, 데이터 로딩·DB 연결 실패와 결과 0건을 사용자에게 안내한다.

### 구현상 제약 및 확인사항

- 저장소 이원화 구조에서 즐겨찾기는 브라우저 단위(`localStorage`)로 동작하므로 브라우저 캐시 초기화 시 초기화될 수 있다.
- 외부 데이터베이스 연결이 제한되는 오프라인/로컬 테스트 환경에서는 대체 안내 또는 로컬 폴백 동작 여부를 확인해야 한다.
- 상세 및 코스 화면의 지도는 샘플 지도 이미지 및 하단 지도 영역 호출이며, 실시간 도보 경로 API의 실시간 계산과는 구분된다.

1. 사용자가 지역·테마·분위기 조건으로 서점을 좁히고 상세정보(주소 복사 아이콘·한 줄 전화번호·하단 지도)를 확인한다.

3. 관심 책방을 저장하고(나의 책방 진입 시 항상 즐겨찾기 우선 노출), 책방과 주변 장소를 활용해 코스를 만들고 지도로 확인·저장한다.
4. 한 화면에서 책방 썸네일(40개)과 코스 이미지(10개)가 중복 없이 랜덤 호출되고 전 화면에서 동일한 비율로 표시된다.
5. 두 데이터 파일을 읽지 못할 경우 오류/재시도 또는 부분 로딩 안내를 제공한다.

### 사이트맵

```text

    ├── 하단 지도 영역
    ├── 즐겨찾기 · 방문 기록

├── 나의 책방 → 즐겨찾기/방문 기록/저장 코스
└── 나의 취향 → 취향 설정
로그인/회원가입 화면
```

### User Flow

- 책방 검색 → 조건 선택 → 목록 비교 → 상세 → 즐겨찾기.
- 저장한 책방 선택 → 코스 조건 설정 → 장소·순서 확인 → 코스 저장.
- 책방 방문 → 후기 작성 → 브라우저 저장.

### 데이터 및 기술

- `data/bookstores.json` **327개**, `data/places.json` **16개**, `data/sharedCourses.json` **7개**.
- HTML/CSS/JavaScript + `localStorage`; 외부 공공 API 수집 스크립트는 아직 없음.
- 후기 데이터의 서버 공유는 구현된 것으로 보지 않는다.

## 2.6 PRD v0.1 — 2026-10-12 (4주차 기획)

> 아래는 당시 7쪽 기획 문서의 **계획 범위**를 보존한 내용이며, v0.1의 실제 구현 완료를 뜻하지 않는다.

### 사용자 문제·시나리오

주말/공강에 추리소설과 조용한 공간을 좋아하는 사용자가 지도 앱, 블로그, SNS를 오가며 책방의 취급 분야·분위기·좌석·음료 여부를 각각 확인해야 한다. 서비스에서 조건을 복수 선택하고 방문자 후기 기반 태그로 판단한 뒤, 책방을 중심으로 산책/휴식 코스를 계획한다.

### 문제 우선순위

1. **취향에 맞는 책방 찾기:** 취급 분야·테마 복수 필터, 책방 특성 태그, 상세보기.
2. **실제 방문 경험 판단:** 체크리스트형 후기, 후기 응답 집계·키워드 요약, 후기 기반 추천 태그.
3. **책방 중심 경험 확장:** 책방 중심 산책 코스, 주변 장소·산책 경로 지도 표시.
4. **개인화·재사용:** 북마크, 방문 기록, 개인 메모.

### 기능 우선순위 (당시 원안)

- **Must:** 책방 목록, 지역 검색, 취급 분야·테마 복수 필터, 책방 특성 태그, 상세보기, 체크리스트 후기, 후기 응답 집계/키워드, 책방 중심 지도.
- **Should:** 책방 중심 산책 코스, 주변 산책로·휴식 장소, 북마크, 방문 기록, 개인 메모.
- **Could:** 취향 기반 책방 추천, 자유 후기 키워드 추출, 책방별 인기 태그 시각화.
- **제외:** 실시간 혼잡도, 실시간 재고/도서 검색, 예약·결제, 유저 생성 코스 공개 공유 플랫폼.

### MVP (당시 원안)

지역 → 취급 분야·테마 → 분위기·공간 조건 → 책방 목록 → 상세·후기 태그 확인 → 즐겨찾기 저장이 **1차 MVP**. 이후 책방 중심 산책·휴식 공간 지도 확인과 코스 구성이 심화 목표.

### 사이트맵 (당시 계획)

```text
홈
├── 책방 탐색
│   ├── 책방 목록
│   ├── 책방 상세
│   └── 방문자 후기/키워드
├── 코스 만들기
│   ├── 코스 조건 설정
│   ├── 지도·코스 결과
│   └── 코스 편집·저장
├── 나의 책방
│   ├── 즐겨찾기·방문 기록
│   └── 저장 코스
└── 나의 취향
    └── 취향 설정·추천
```

### User Flow (당시 계획)

- **흐름 A · 취향에 맞는 독립서점 찾고 저장:** 서비스 진입 → 지역 선택 → 취급 분야·테마·분위기·시설 필터 → 카드 비교 → 상세·후기 확인 → 즐겨찾기 저장.
- **흐름 B · 저장한 책방으로 독서·힐링 코스:** 나의 책방 → 즐겨찾기 선택 → 산책/독서 체류 조건 설정 → 지도·코스 결과 → 이동 정보 확인(지원 시) → 장소/순서 편집 → 코스 저장.
- **예외 흐름:** 로딩, 결과 없음, JSON/클라우드 DB/지도 API 오류, 저장 실패, 후기 부족, 지도/경로 API 미지원 시 안내와 재시도 제공.

### 데이터·외부 연계 (당시 계획)

- **JSON:** 서점 기본정보·상세·위치.
- **Supabase/Firebase 등 클라우드 DB:** 여러 이용자의 후기 저장·조회·집계 **계획**.
- **지도 API/경로 API:** 책방 마커·주변 장소·도보 경로·예상 시간 **계획**, 지원 여부 확인 필요.
- **LocalStorage:** 즐겨찾기·코스·취향 등 개인화 저장 **계획**.

# 3. 공통 개발·운영 정보

## 3.1 기술 스택

- **프런트엔드:** HTML5, CSS3, JavaScript

- **API·뉴스 데이터 수집:** Python, 문화공공데이터광장 OpenAPI, Google 뉴스 RSS 수집 및 GitHub Actions 자동화
- **데이터 저장 (이원화 구조):**

  - **외부 데이터베이스(Cloud DB) / 정적 데이터 스토어:** 회원·후기·코스·방문 기록 등 영속 데이터 및 공통 JSON 데이터
- **실행/배포:** 로컬 정적 웹서버(VS Code Live Server 등), GitHub Pages에 배포 가능한 구조

## 3.2 생성형 AI 도구

프로젝트의 기획·설계·개발 보조에 활용하는 생성형 AI 도구:

- **ChatGPT** — 기획 정리, 요구사항/문서 작성, 코드·디버깅 지원
- **Claude** — 구현 검토, 코드 개선, 개발 보조
- **Gemini** — 아이디어 검토, 기술·구현 보조

세 도구 모두 사용한다. **버전별 개별 프롬프트·담당 기능·실행 결과는 별도의 사용 기록이 확인되는 범위에서만 기재**한다. 특정 AI가 특정 코드를 작성했다고 근거 없이 단정하지 않는다.

## 3.3 실행 방법 (v0.6)

1. 프로젝트 폴더를 VS Code에서 연다.
2. `index.html`과 같은 위치에 `data/`, `css/`, `js/`, `asset/`(하위 `thumbnails/` 40개, `courses/` 10개 포함)가 있는지 확인한다.
3. Live Server 또는 로컬 HTTP 서버로 `index.html`을 실행한다. 파일을 직접 더블클릭하는 `file://` 방식은 JSON `fetch`가 제한될 수 있다.
4. 책방 탐색에서 300개 서점 로딩, 비중복 랜덤 썸네일, A/J 배지, 즐겨찾기(`localStorage`) 및 데이터 저장 동작을 확인한다.

## 3.4 API 및 새소식 자동 갱신 (v0.6)

### 1) 문화공공데이터광장 API 갱신 (v0.3 이상)
`KCISA_SERVICE_KEY` 환경변수를 설정한 뒤 `python scripts/fetch_bookstores.py`를 실행해 API JSON을 갱신한다. 수집 결과는 검토 후 반영한다. **서비스 키를 README, JSON, 브라우저 JavaScript 또는 공개 GitHub 저장소에 넣지 않는다.**

### 2) 새소식 자동 수집 (GitHub Actions, 2026-11-23)
- **워크플로:** `.github/workflows/update-news.yml`
- **실행 주기:** **3시간마다** (UTC 00/03/06/09/12/15/18/21시 = 한국시간 09/12/15/18/21/00/03/06시), 또는 GitHub **Actions → Update bookstore news (every 3 hours) → Run workflow** 수동 실행. GitHub 스케줄 실행은 혼잡 시 지연되거나 누락될 수 있음.
- **처리 방식:** `python scripts/fetch_news.py` → Google 뉴스 RSS에서 최근 기사 수집 → `data/news.json` 갱신 → 변경된 경우에만 자동 커밋 및 푸시. 표준 라이브러리만 사용하므로 별도 패키지나 API 키 불필요.
- **예외 처리:** 수집 실패 또는 검색 결과 없음 시 스크립트가 오류 종료하며 기존 `data/news.json`을 보존하고, Actions 실행은 실패로 표시됨.
- **GitHub 설정:** 저장소의 **Settings → Actions → General → Workflow permissions**에서 **Read and write permissions** 허용 필요 (기본 브랜치에 워크플로 업로드 필수).
- **주의:** 새로고침할 때마다 외부 뉴스를 실시간 수집하는 방식이 아니라 약 3시간 간격으로 갱신된 `data/news.json`을 읽으며, `updatedAt`은 수집 시각을 의미함.

## 3.5 데이터 품질·보안 주의사항

- 외부 API에서 가져온 정보는 수집 시점의 정보이므로 방문 전 실제 영업 여부를 확인해야 한다.
- 서점 데이터의 누락값을 임의로 만들어 채우지 않는다.
- 즐겨찾기(`localStorage`)와 외부 데이터베이스(Cloud DB)에 저장되는 데이터의 권한·동기화 범위를 구분해 관리한다.
- 외부 DB 및 API 키는 공개 저장소 코드에 하드코딩하지 않는다.
- 새로운 버전에서는 데이터 수, 중복 기준, 필드 구조, 저장 위치, 폴더 변경을 변경이력에 함께 기록한다.
